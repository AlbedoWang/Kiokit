# Development

## Layout

- `OpenAnkiIOS/Application`: launch, navigation, and the observable UI store.
- `OpenAnkiIOS/Features`: Decks, Cards, Review, Statistics, and Settings screens.
- `OpenAnkiIOS/Shared`: reusable SwiftUI components and the theme.
- `OpenAnkiIOS/Platform`: iOS audio, WebKit, and document bindings.
- `Core/Sources/OpenAnkiCore`: Backend, Collection, Session, Frontend, Models,
  Localization, and Migration layers.
- `Core/Sources/OpenAnkiCore/Resources`: original web assets, translations, and
  offline license notices.
- `Backend`: Rust FFI transport and the pinned Anki submodule.
- `Scripts`: builds, resource preparation, original fixture generation, and
  verification against upstream.

Screens delegate through the UI store to the core session and Anki backend.
Collection data, scheduling, queues, limits, undo, import, and graph calculations
remain upstream. The Swift snapshot and rendering cache are display projections.
Card Details omits the native FrontSide replacement in its Back panel only;
ordinary reviewer rendering and stored templates remain unchanged.

## Upstream and licenses

Anki is pinned to **26.09.3**, commit
`29bb700b951e3f0c0cb69b77c0180fc1fe33e6ba`. Relevant source paths are recorded in
[Backend/upstream.json](../Backend/upstream.json). Bundled frontend assets come
from the checksum-verified official distribution and are unchanged.
[AGENTS.md](../AGENTS.md) defines the constraints on domain logic.

The repository is AGPL-3.0-or-later; original dependency notices remain under their
own licenses. See [NOTICE.md](../NOTICE.md). After building the backend and
resolving SwiftPM packages, regenerate offline notices with:

```sh
python3 Scripts/prepare_licenses.py
```

The original app icon and transparent interface mark share one drawing:

```sh
swift Scripts/generate_icon.swift
```

Personal signing settings belong in the ignored `Config/Local.xcconfig`, copied
from `Config/Local.xcconfig.example`. User account credentials, test collections,
build outputs, and Xcode user settings must not be committed.
After staging changes, run `python3 Scripts/check_publishable.py` before pushing.

## Verification

```sh
swift test --package-path Core
python3 Scripts/verify_upstream_dependencies.py
python3 Scripts/verify_web_frontend_parity.py
```

Additional scripts verify backend responses, rendering, typed answers, audio,
and timer behavior against the actual pinned Anki implementation. The Python
backend checks use the matching official `anki==26.9.3` wheel, as documented in
each script. UI tests use the `OpenAnkiIOS` scheme on an iOS simulator; set
`-collect-test-diagnostics never` when invoking `xcodebuild test`.

Optional external-deck tests read `OPENANKI_TEST_APKG` at runtime. Keep supplied
decks outside the repository or in the ignored `LocalDecks` directory. Committed
APKG/COLPKG fixtures contain original authored content generated by the scripts.

Full application parity remains under verification. Desktop Python add-ons,
external TeX tools, and Auto Advance are not exposed on iOS. Native imported
options and template data are retained. Device audio/voice support comes from
iOS. Simulator checks do not establish physical-phone behavior.
